# Commit message for t_2bd5daf9 (D15)

Gate the progress bar off the archive: it rendered a false 0% the whole way down

Audit D15. `/sittings/index.html` emitted a `.pbar` that was `display:block` at
desktop widths and read `0%` / `aria-valuenow="0"` at the top AND at the bottom
of the page. The percentage comes from `scrollY / (scrollHeight - innerHeight)`
and is written by `pbarSync()`, which the archive never reached: the page carries
no `data-page` and no `SCRIPT` at all, so no scroll state is ever written for it
and the bar sat at its server-rendered value forever. A bar reporting a number
that is wrong is worse than no bar, so it is gone rather than fixed.

Decision: option 1, gate it. Recorded in `render_archive()` beside the removal.
The archive is not a piece of reading to make progress through -- it is ~2770px of
scroll at 1280, already grouped into year disclosures -- and it has no scroll
behaviour to report on. That is the same reason `.section-rail` and `.totop` are
absent from this page: the archive already gated its chrome in one place and not
another, and this makes it consistent. Option 2 (make it real) would have meant
inventing a metric for a page that does not need one.

Verified, not asserted:

  * tools/qa_build_diff.py against a fresh build of the same commit:
    3847 of 3848 files byte-identical; the only change is `sittings/index.html`,
    and the new file equals the old with exactly the 5-line `.pbar` block excised
    (string equality, not a diff heuristic). No other page or byte moved.
  * tools/qa_d15_pixels.py: with the fixed chrome suppressed, the archive and a
    sitting page are pixel-identical before and after at the same scroll offset,
    at 1280 and 1440 -- 0px differ across 900 rows x 4 runs.
  * `.pbar` on a sitting page still reaches 100% at the foot at 1280 and 1440.
  * tools/qa_archive_pbar.py: of 339 generated pages, 0 emit a bar with nothing
    driving it; the archive has none; all 331 sitting pages keep theirs.
  * tools/qa_console.py: silent console, no horizontal overflow, no top-bar shift
    at all 8 widths. tools/check_column_guides.py and tools/qa_pixels.py still pass.
  * The check itself is not vacuous: qa_defects.py's D15 block FAILS on the
    pristine pre-change build (bar present, reads 0 at the foot) and passes here.

D15 is now an assertion rather than a print, at 1280 and 1440, and it asserts both
halves: the archive may not render a bar that misreports, and the sitting page may
not lose its bar.

The `aria-label` was "Progress through this sitting" on a page that is not a
sitting -- removed with the element.

`site/dist/` is not in this commit: 27 tracked dist files were already stale
against a fresh build of this commit BEFORE the change (proved by rebuilding the
unmodified commit in a detached worktree and getting the same 27), so that drift
is pre-existing and unrelated.
