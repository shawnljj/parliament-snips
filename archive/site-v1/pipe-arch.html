Parsnips — how a day of Parliament becomes a checkable brief

Sitting → Section → Speaker → Sentence → Claim. Deterministic everywhere it can be, a model only where judgement is required.
Schema v3 · model deepseek-v4.1-flash:cloud · every number on this page is measured at build time.

The problem is not summarisation. A language model summarises Hansard well enough. The problem is that a summary you cannot check is indistinguishable from one that is wrong — and a wrong claim about what a minister said is the one failure this project cannot ship. So the design question was never "which model", it was "what can be made structurally impossible, and what has to be verified". This page is the answer: the four stages, the gates that fail closed, and the two separate checks that stand behind every published sentence.

02The summarising algorithm

Four stages. One of them uses a model. The other three are ordinary code that either passes or refuses, and the refusal is the point — a brief that fails a gate is withheld rather than published with a caveat.

Stage 1 · build the corpus deterministic · offline
Parse Hansard into items, turns and sentences. Every sentence gets a stable id and a character span into the archived source. Nothing downstream ever quotes text it did not receive from here.
Stage 2 · extract by reference the only model stage
The model reads a chunk and returns sentence ids plus its own paraphrase — never a quotation. Quote text is substituted from the record afterwards, so a fabricated quote is not caught, it is unrepresentable.
Stage 3 · assemble deterministic
Resolve every cited id, attach each citation's own text, cap the point count against the item's reading budget, drop duplicates, and record a reason for every exclusion.
Stage 4 · verify and gate deterministic · fails closed
Re-slice the source at each cited span, compare hashes, check coverage and schema completeness. Any failure withholds the brief. Four gates, all failing closed.

Stage 2 in detail — why the model never writes a quotation

This is the single design decision the rest of the system is built around. Asking a model to quote asks it to reproduce text, and the failure mode is a plausible sentence that appears nowhere in Hansard — which reads exactly like a correct one. So the model is asked for a reference instead: 

Sentences from the record, each prefixed with its id:
  s41: The PSGA was introduced in 2018 to enable public agencies to share data safely.
  s42: It applies to all public agencies unless expressly excluded.

Return, for each claim, the ids of the sentences that support it.
Cite the fewest sentences that support the claim.

The model returns a claim and a list of ids. The pipeline then reads those sentences out of the record and uses that text as the quote. The model's paraphrase is kept as the human-readable claim; the quotation is never the model's.

What this eliminates: the entire class of fabricated-quote error. A model cannot invent a quotation it was never asked to produce. What it can still do — and does — is misread a real sentence, which is why Stage 4 and the separate citation verifier exist.

The reading budget

A brief is capped by how long the item is, not by a flat number of points. The requirement is roughly ten seconds of reading per turn of the record: a one-turn item gets one point, a 60-turn motion may carry sixty. A flat cap would either truncate long items or pad short ones, and both read as a system that does not understand its own input. Chunked items are capped by selecting across chunks (coverage-aware, falling back to round-robin) so no single chunk supplies everything.

Prompt size is a correctness parameter

Chunks are bounded at 6,000 characters. This is not a performance tweak. At ~24k characters the model produced citation lists of eighty-plus ids and roughly a fifth of replies arrived truncated and unparseable; at 6,000 the same work is clean. Longer replies are capped at 900 tokens for the same reason — one chunk once generated 35,420 tokens in a repetition loop and never stopped.

03The verifying algorithm

There are two independent checks, and they are deliberately different in kind. A gate can prove structure. It cannot tell you whether a sentence means what the claim says it means. That is a separate job, done by a separate agent.

Check 1 — the deterministic gates

All four run in Stage 4 and fail closed: a failure withholds the brief.

Gates stage4_verify
GateWhat it proves
quote invariant For every point: re-slice the archived source at the cited span and compare sha256 with the quoted text. This is what makes a quote proven rather than trusted, and it is re-runnable after publication.
citation resolves Every cited id exists and belongs to this item. Catches a model citing a sentence from elsewhere in the corpus.
coverage floor The brief must account for a real share of its item — floor 0.15 of turns, and at least 1 turn(s). Added after a one-point brief covering 1 of 62 turns passed and published.
schema complete Every field the site renders is present. Derived from what the renderer actually reads, so a field the site consumes can never quietly go missing.

What the gates caught that no test would have

  • Every multi-citation point failed. Assembly stored one quote but listed all cited ids, so the verifier compared sentence 2's words against sentence 1's id. The gate was right and the code was wrong — it found a real bug on its first run.
  • A question reported as a finding. A brief claimed "The Government is assessing how rising fuel costs are passed through" where the source said "asked the Deputy Prime Minister whether…". Across the year, 214 points cited a question and 18 asserted a fact from one. Fixed in the prompts so the claim stays in the asking register, and flagged in Stage 4.
  • Silent schema regression. 96 briefs were missing four item-level fields. Every field the site reads is optional, so the pages rendered complete and looked fine. Invisible to the eye, caught by a gate.
The lesson these share: a gate is only as good as its ability to fail. Each of those three was found by a check that was expected to pass.

Check 2 — the citation verifier

The gates check structure and never meaning. So a second agent judges each claim against the sentences it cites and returns a verdict: supported, weak, unsupported or reversed, plus a defect class such as dropped_qualifier, overstates or wrong_speaker.

Its prompt is adversarial by construction: the reader is told to find the way the claim overstates the source, and a claim that drops a hedge — "who sits at the table potentially decides" becoming "decides" — is reported as dropped_qualifier, not as supported. It found exactly that class of error in the published corpus.

On independence — an honest note. The verifier was originally a different model family from the writer, so that the same blind spots could not judge themselves. Cost won: it now runs on deepseek-v4.1-flash:cloud, the same model that writes the briefs. That weakness is not assumed away — it is tested. The verifier is scored against a ground-truth set of known-good claims and deliberately planted defects, including the original question-as-fact error, and it must keep catching them. A different role (judge rather than author) and an adversarial prompt are what carry it now; if the score falls, the test says so.

Why the verifier retries instead of giving up

The model sometimes returns fewer verdicts than claims in a batch — silently, with valid JSON. On the first full-size run this left 33.4% of claims unjudged, and because the summary counted them in the denominator, a run that had examined two-thirds of the corpus read as though it had examined all of it. Two fixes, both now load-bearing:

  • A short reply is a partial failure. The batch is re-asked for only the missing indices, so recovering a third of a batch costs a third of a batch. Bounded, so a model that refuses outright cannot loop forever.
  • An unjudged claim is never cached. Caching it made the retry a no-op: the skipped claims were read back as already answered, so re-running asked nothing and coverage never moved. Absence of a result is not a result.
The reporting rule this produced: coverage is printed next to the supported fraction, and both are stated — supported-of-all and supported-of-judged — with a warning below 99%. A verifier that samples must say that it samples.

04Pipeline, entities, schema

01Pipeline architecture

Five stages. Three of them involve no model at all — the mechanical work is deterministic and reproducible. The model appears once, in Stage 2, and it returns sentence ids rather than quotations: the assembler substitutes the stored text afterwards. That is what makes every published quote verbatim by construction (R-2.1, R-2.2).

02Entity relationships

One chain gives provenance: sitting → report → turn → sentence. Everything derived hangs off it and refers back by id. There is no entity called "brief" with its own copy of the text — a claim points at the sentences it rests on.

Why there is no “brief” entity holding its own text. If a brief stored a copy of the words, the copy could drift from the record and no check would catch it — that is precisely how a reworded quotation would enter the system. Instead a claim stores only an assertion plus the ids of the sentences it rests on; the quotation is substituted from sentence.text at assembly time. A model that mangles a quote in its head has no way to publish the mangled version.
