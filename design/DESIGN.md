# DESIGN.md — parsnips case study

The style contract for `site/case-study.html`, generated by
`site/build_case_study.py`. Read this before editing the page. If you change a
token or a pattern here, change it in the generator, not the built HTML.

## Register and voice

**build**, not direct. One conventional surface.

**Voice: a blog post, not a research paper.** This is the constraint most likely
to be broken by a later edit, because the material invites over-writing. Rules:

- Write about **the architecture and the decisions**, not the implementation
  detail. No schema tables, no defect-id taxonomy, no "measured on the heavy item,
  16/24 with raw text and a capped transcript" strings.
- Six sections, first-person where a decision was mine ("my first design had code
  pick the important sentences"). Sections are `why`, `output`, `provenance`,
  `shape`, `lessons`, `where`.
- Failures are **"Things that went wrong"** — a short numbered list of three
  lessons with a takeaway each, not case studies with code blocks.
- **"What the data actually looks like"** shows five real records (sitting →
  report → turn → sentence → item) as JSON blocks, generated from the archive.
  This is the one place code-shaped output belongs on the page, because the data
  shape *is* the subject. It sits after the pipeline section, before the failures.
- Every number must still be computed (see below), but a figure earns its place
  only if it supports a sentence. The hero ledger, one example claim, and the
  status list are enough.

The earlier version of this page was a 920-line research paper. It was correct and
unreadable. Do not rebuild it.

## The non-negotiable: mobile first

**The base layer of the stylesheet IS the 390px layout.** There are exactly two
`min-width` blocks; nothing else may assume width. Concretely:

- Base CSS has no `max-width` overrides — that would be desktop-first.
- The ledger row is `grid-template-columns: 1fr` with the figure `order: -1`
  (figure above claim). The two-column form arrives at `min-width: 620px`.
- Tables are full-width blocks at base; the `120px 1fr` status grid arrives at
  620px.
- The failure case studies are full-bleed from 900px via `calc(50% - 50vw)`.

### Measured type values (do not "improve" without re-measuring)

At 390px the content column is 362px (14px gutters). Measured line boxes:

| viewport | body size | chars per line | target 45–75ch |
|---|---|---|---|
| 390px | 15.5px | ~40 | low end, acceptable |
| 768px | 17px | ~73 | in range |
| 1440px | 17.5px | ~74 | in range |

A canvas-based `measureText` estimate said 39ch when the real figure was 32ch —
**it was wrong because it averaged over the letter "n" instead of measuring real
line breaking.** Always measure with `Range.getClientRects()` on a real
paragraph, or by cloning text into a same-styled offscreen node. Do not trust an
analytic estimate here.

## Type

| role | face | notes |
|---|---|---|
| display (h1, h2, h3, figures, pull-quotes) | **Newsreader** (variable, Google Fonts) | `clamp()` sizes, `-0.02em` to `-0.03em` tracking |
| body | system stack (`-apple-system, BlinkMacSystemFont, Segoe UI, Inter…`) | the product's own stack; 15.5px mobile → 17.5px desktop |
| mono | `ui-monospace, SFMono-Regular, Menlo` | **only** for code, hashes, file paths, requirement ids |

Mono is confined to where monospace is semantically correct. There are no mono
service labels, no eyebrow kickers beyond the single section stamp, no `01 / 02 /
03` counter chrome (the section numbers are real sequence, so they stay).

## Colour

Single hue family on a lit ground. Background mean L ≈ 0.98.

```
--ink    #14181d   body text          17.21:1 on bg
--dim    #5c6773   secondary prose     5.57:1
--meta   #657080   provenance/meta     4.85:1   (NOT --faint: #8b95a1 is 2.93:1 and fails)
--faint  #8b95a1   decorative rules only — never text
--accent #1c6b4a   green: verified / deterministic / links   6.24:1
--warm   #a4551f   withheld / failure  5.20:1   (NOT #b4622a: 4.30:1, large-text only)
--bg     #fbfbfa   page
--card   #ffffff   raised surfaces
--rule   #d8dee4   ledger hairlines
```

**Two semantic colour roles only:** green = passed/verified/deterministic, amber =
failed/withheld. The old box diagram used four decorative colours
(cyan/amber/violet/rose); they are gone. Every remaining colour carries meaning.

**Contrast is verified, not assumed.** All 20 foreground/background pairs are
checked ≥ 4.5:1 before shipping. Body text on a tinted ground is the #1
readability failure; `--meta` exists because `--faint` fails it.

## The signature element

`#insp` — the provenance inspector. Four steps that illuminate in sequence,
driven by a **real precomputed result** (the hashes were computed at build time
from the archive), not a timer pretending to work. Its rules:

- The verdict block ships as static markup and is revealed by a class; with JS
  disabled the page is still complete and readable (verified).
- `prefers-reduced-motion: reduce` keeps every state change and removes only
  travel (gap 520ms → 90ms). Verified: the check still completes and the verdict
  still appears.
- Numbers shown in it (`char_start`, `char_end`, digests, lengths) are emitted by
  the generator. Never hand-edit them.

## Gotchas found the hard way

- **Table identifier cells must use `overflow-wrap: break-word`, never
  `anywhere`** — `anywhere` broke schema tokens mid-word at 390px. (Tables are
  gone from this page now, but the rule stands if one returns.)
- **Code blocks must wrap below 520px** (`white-space: pre-wrap`). An evidence
  page must not hide its evidence behind a sideways swipe.
- **The generator runs on Python 3.9.** No backslash escapes inside f-strings
  (`\u00b7` in an f-string is a SyntaxError there). Separators are module
  constants: `MIDDOT`, `DASH`.
- **The `.verdict` block must sit INSIDE `#insp`.** A stray `</div>` in step 4
  closed the container early, so `.insp.done .verdict` silently stopped matching
  and the verdict never appeared. After editing that markup, check the tag counts
  in the built HTML.
- **Verify the built file, not the source.** Several times a CSS fix looked
  applied but the measurement was reading a stale build. Run the generator, then
  measure.

## The data sample section

`.sample` / `.sstep` / `.code` / `.snote` — five real records.

- Values come from `build_data_sample()`, which reads the sitting JSON and the
  stage-1 dataset at build time. Nothing is typed.
- The turn shown is the one containing the quoted claim, so the sample explains
  the example above rather than introducing a second story.
- **Do not shorten a value without saying so.** The turn's speaker label is shown
  in full on purpose — its verbosity is the point (D-6 keeps the recorded string).
  The one clipped value (the sentence's speaker) is declared in its note.
- **`.code` uses `overflow-wrap: break-word`, never `anywhere`.** `anywhere` split
  strings mid-word, which makes real data look corrupt.
- The blocks wrap rather than scroll at every width: measured, 3 of 5 scrolled at
  768px because one unbroken speaker label exceeds the column.

## The recurring evidence device

`.ledger` / `.row` — a claim, the command that reproduces its figure, and the
figure. Used in every section. Rules:

- **Provenance strings are escaped text**, so they must use plain characters
  (`·`, `–`, `×`) — never HTML entities. An entity there renders literally as
  `&middot;`.
- `claim` and `fig` are trusted markup and may carry `<b>`.
- Mobile: figure first.

**Every figure on the page is computed at build time.** Requirement N-3 forbids
hand-written self-reported metrics, and defect F-4 is what happens without it.

## Motion

Two families, both bound to content:

1. **Ledger reveals** — none by default (the ledger is readable immediately). If
   added, key them to the list order with 40ms stagger.
2. **Inspector sequence** — the only storytelling motion on the page.

Banned here: `transition: all`, `scale(0)` entrances, `ease-in` on UI,
`window.addEventListener('scroll')` scrubbers, marquees, scroll-instruction
footers. Only `transform` and `opacity` animate. UI durations ≤ 300ms except the
inspector's deliberate step sequence.
